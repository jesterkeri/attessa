Check a
settlement

Attessa lets an agent pay a service only when the answer is signed by the code the seller approved. Paste a call's settlement transaction, and when live, the explorer checks its on-chain part from public Celo data: who paid, which address was paid, how much, and in which block. An address alone doesn't tell which endpoint or build answered; that needs the call's proof. No wallet, no payment. Planned: looking a call up by its request ID and checking its proof, which needs a public copy of the proof that nothing serves yet.

0x and 64 hex characters. When live, it checks against Celo Sepolia. Celo mainnet comes after launch.

The five checks it runs

  1. Approved buildregistry, planned
  2. Sealed machineAWS attestation, planned
  3. This exact request and answersigned hashes, planned
  4. Real Celo datablock read, planned
  5. Paymentsettlement

When live, it runs the payment check. The other four are planned.

UI previewSample states, not a check of any transaction: pick one to see how each result looks, with sample slots. Nothing is read from Celo yet for the rejected states: they need request-ID lookup and the call's proof, which are planned.

Recent calls

When live, it lists the latest settlements, read from Celo events. Each row shows what Celo shows: the payment and the address paid, not the endpoint or the proof. A refused call usually has no settlement, so it usually isn't listed here. If it was your call, your own record has it: attessa status shows your recent verdicts (Coming).
