{{i:pass}}What a proof shows

  • {{i:yes}}Which approved build answered, for this request, with these inputs.
  • {{i:yes}}That it ran in a sealed machine, attested by AWS, with its key registered on Celo.
  • {{i:yes}}Which Celo data it used, read at a stated block and bound by hash. Re-reading that block is what checks the values, when your RPC still has it.
  • {{i:yes}}Whether you paid, or your payment permission expired unused. Anyone can read this on Celo, given the payer's address and the permission's nonce. Both are in your own record, and the nonce is also in the proof the gateway publishes.

{{i:na}}What it doesn't show

  • {{i:no}}That the answer is correct. A bad answer is a rules problem you can read in the source.
  • {{i:no}}That the service is available. An operator can still withhold or delay answers.
  • {{i:no}}That the build matches its source. That link is the owner's claim, shown as "Owner says it's built from github.com/… @ commit" until someone reproduces the build.
  • {{i:no}}That requests are private. Request bodies are visible to the service's gateway and to the server the sealed machine runs on.
  • {{i:no}}Protection when paying through buy. buy, Celo's marketplace of pay-per-call APIs, takes payment before the service runs, so Attessa can only check afterwards.
  • {{i:no}}An instant "not charged". After a refusal, confirming it takes up to about two minutes, or you can cancel on chain for a little gas.
