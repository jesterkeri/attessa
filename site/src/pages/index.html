    Approved build Sealed machine Signed answer

    It's a check your agent runs before paying for a service: pay only if the answer was signed by the build the seller approved, running in hardware the seller can't tamper with.

    A seller runs their service in a sealed machine and approves that exact build on Celo. Your agent pays only when an answer comes back signed by that build, and anyone can re-check the call later from public Celo data and the proof its gateway publishes.

    1. The seller approves one exact build.

      They publish its fingerprint on Celo. From then on, buyers only pay for answers from that build.

      release, measured as PCR0 to PCR2

    2. It runs in a sealed machine.

      A cloud computer its operator can't log into or change. AWS attests to exactly which build is running.

      AWS Nitro enclave, attestation

    3. Every answer comes back signed.

      The machine signs the request, the answer, the Celo data it read and the payment, all together.

      EIP-712 proof

    4. You pay only if the proof checks out.

      Your agent's payment permission moves no money by itself. The gateway uses it only after all four checks pass.

      x402 quote, EIP-3009 permission

    5. Tampered answers never get paid.

      If the answer doesn't match what was signed, the gateway refuses to settle. The permission expires unused, and once Celo shows that, you're not charged.

      response_hash_mismatch, not_charged

    Every call ends one of three ways

    These are the three outcomes in the demo, and where each one's record lives. Two of them you can check on Celo yourself.

    1. Verified and paid

      Every check passes, so the payment goes through. Its record is the settlement transaction on Celo.

      {{track:pass pass pass pass paid}} See it on Celoscan sample

    2. Tampered and refused

      The answer doesn't match what the sealed machine signed, so the gateway doesn't settle. There is no transaction: the payment permission expires unused, which anyone can read on Celo (authorizationState).

      {{track:pass pass fail na free}} Check it on Celo sample

    3. Unapproved build

      The machine runs a build the seller never approved on Celo, so the registry refuses to register its key and it can't sell a single call. The demo shows this on a local copy of Celo, so it leaves no record on Celo.

      {{track:fail na na na free}}

    What this proves, and what it doesn't

    A proof records which code produced an answer. That's narrower than "the answer is right", and we say so. Every known limit is on the security page.
